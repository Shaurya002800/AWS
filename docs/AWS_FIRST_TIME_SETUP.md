# First-time AWS setup for RewindGuard X

Updated 20 October 2026. The owner requires **zero out-of-pocket paid spend**. This guide separates account setup from project resource deployment. The current repository is **not ready for a full AWS deployment**: `infra/core.json` defines only the DynamoDB table, private versioned S3 bucket, SQS queue, and dead-letter queue. Workflow ARNs, IAM roles, Lambda packaging, RDS restore isolation, and production authentication still need implementation and review.

## Which signup path applies

AWS currently has two distinct signup experiences. **Sign up for AWS (new)** creates a project owned by an AWS Builder ID, with no root user for the project account and an AWS-assigned Region. Its security settings are under AWS Settings → Profile → Manage profile → Security. **Sign up for AWS (advanced)** creates a traditional account with a root user and selectable Region. Its root MFA is under the root account menu → Security credentials. Do not follow root-user instructions on a Builder ID project or create a new account merely to find a root login. [Compare sign-up options](https://docs.aws.amazon.com/accounts/latest/reference/sign-up-for-aws.html).

**Observed owner state, 20 October 2026:** the first, Builder ID project showed Free plan and credits, but address verification failed and a later sign-in produced an account error. A second, advanced account reached the root console and MFA registration, but its billing pages redirected to an incomplete-registration screen. The signup returned to UPI AutoPay verification, step 3 of 5; the owner said they had not completed that step. The second account's active plan, credits, and service access are therefore **unverified**. No project resources have been created. Do not record account IDs, payment details, or identity documents here. A duplicate account may not qualify for a second Free plan; if only Paid is offered, stop. [Free Tier FAQ](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/free-tier-FAQ.html).

## Stage 1 — Create and secure the account (do this now)

1. Choose the signup path deliberately. The [advanced signup page](https://signin.aws.amazon.com/signup?request_type=register) is appropriate if a selectable Region and full account controls are required. Use an email and password that only the owner controls. Complete contact, payment-method, identity, and phone verification personally. AWS may place a temporary verification authorization on the payment method. If AWS says this identity is ineligible for the Free plan, **stop** before selecting Paid. [Advanced signup](https://docs.aws.amazon.com/accounts/latest/reference/getting-started.html), [Free Tier FAQ](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/free-tier-FAQ.html).
2. Select **Free account plan** and **Basic Support** when offered. The Free plan currently prevents out-of-pocket service charges during its eligible period, but ends after six months or when credits run out, whichever occurs first. Never click **Upgrade plan** for this project without revisiting the zero-spend rule. [AWS plan comparison](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/free-tier-plans.html).
3. For an advanced account, sign in as root once and set up MFA immediately: account menu → **Security credentials** → **Assign MFA device**. For a new-experience project, secure the Builder ID instead. Prefer a passkey/security key if available; an authenticator app also works. Save recovery information privately. Do not share a password, MFA code, account ID, or payment details in Git or chat. **Do not create root access keys.** [AWS root MFA instructions](https://docs.aws.amazon.com/IAM/latest/UserGuide/enable-mfa-for-root.html), [Builder ID MFA](https://docs.aws.amazon.com/signin/latest/userguide/mfa-builder-id.html).
4. Do **not** create or join AWS Organizations or enable an organization instance of IAM Identity Center on a Free plan. AWS says creating an organization can automatically upgrade a Free account to Paid and expire its Free Tier credits. We will choose a safe day-to-day access method before connecting a CLI or Codex. [AWS plan comparison](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/free-tier-plans.html), [Identity Center setup](https://docs.aws.amazon.com/singlesignon/latest/userguide/enable-identity-center.html).
5. In **Billing and Cost Management**, record privately: account plan, remaining credit amount and expiry, Free Tier usage, and whether any charges already appear. Under **Budgets**, create one **Zero spend budget** with email alerts; check **Billing preferences** for Free Tier usage alerts. Budget alerts monitor spending and do not guarantee a hard stop. Avoid paid Budgets Reports or extra action-enabled budgets. [Free Tier tracking](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/tracking-free-tier-usage.html), [Budgets pricing](https://aws.amazon.com/aws-cost-management/aws-budgets/pricing/).
6. Choose one Region for the project after confirming availability and cost in the console. **Asia Pacific (Mumbai), `ap-south-1`, is a candidate for an India-based owner, not a commitment.** The first new-experience project was assigned Sydney; its Region cannot simply be changed. An advanced account permits Region selection. Keep all project resources in one Region. Record only the chosen Region and non-secret plan facts in `docs/PROJECT_CONFIG.md`. [Project Regions](https://docs.aws.amazon.com/accounts/latest/reference/project-regions.html).

For the advanced account currently in progress, finish or replace the required payment verification only after checking that **Free plan** was selected. UPI AutoPay authorization permits automatic payment of future AWS India bills up to its mandate limit; the limit is not an immediate charge. If the owner does not accept that mandate, inspect the offered card option instead. Completing root MFA alone does not complete account activation. If all signup steps are complete but billing still redirects, check for an AWS activation/request email and use AWS account support after the stated activation window. [AWS India payments](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/edit-aispl-payment-method.html), [advanced signup](https://docs.aws.amazon.com/accounts/latest/reference/getting-started.html).

**Stop after Stage 1.** Send back only: whether AWS shows **Free plan** or **Paid plan**, the chosen Region, whether credits are active and their expiry date, and whether the zero-spend alert is set. Do not send credentials, card details, account ID, or billing screenshots containing private information.

## Stage 2 — Resource deployment (later, after code and account gates)

| Order | Service | Project purpose | Current state |
| --- | --- | --- | --- |
| 1 | CloudFormation, IAM | Controlled infrastructure and least-privilege roles | Core template exists; service roles incomplete |
| 2 | DynamoDB | Independent EraseLock authority | Adapter fake-client tested; no live test |
| 3 | S3 | Private versioned synthetic documents | Version-aware adapter fake-client tested; no live test |
| 4 | SQS + dead-letter queue | Delayed/replayed profile events | Worker tested with fake SQS and local PostgreSQL |
| 5 | RDS PostgreSQL | Live database and isolated old restore | Local PostgreSQL tested; no RDS provisioning/restore code |
| 6 | Lambda, Step Functions, EventBridge | Cloud execution and recovery events | Offline task boundaries/reference definitions only |
| 7 | CloudWatch | Scoped operational logs and alarms | Local audit only |
| 8 | KMS or other signing mechanism | Cloud evidence authentication | Local HMAC only; no KMS signature |

The first four data resources are declared in `infra/core.json`. **Do not deploy it yet.** When the code and account gates are complete, the owner can install AWS CLI v2, use a non-root, short-lived credential method, validate the template, review a CloudFormation change set, and create the stack only if the exact usage remains within the verified zero-spend boundary. The template does not deploy a working cloud application. [AWS CLI installation](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html), [AWS CLI credential prerequisites](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-prereqs.html).

Cost traps to assess before Stage 2: every retained S3 version consumes storage; an RDS instance and restored candidate may consume credits; NAT gateways have hourly and data charges; customer-managed KMS keys have a monthly charge. These must be absent, replaced, or covered by verified account allowances/credits before deployment. [S3 Versioning](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Versioning.html), [RDS Free Tier](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/Welcome.html), [VPC pricing](https://aws.amazon.com/vpc/pricing/), [KMS pricing](https://aws.amazon.com/kms/pricing/).
